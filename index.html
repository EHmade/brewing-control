About & References

Coffee Brewing Control은 맛에 대한 관찰과 추출 데이터를 연결해, 원하는 커피를 향한 다음 추출의 판단과 조정을 돕는 브라우저 도구입니다. 설치·로그인 없이 사용할 수 있으며, 지원되는 브라우저와 운영체제에서는 측정기의 TDS를 직접 입력받을 수 있습니다. 타겟 범위는 맛이나 품질을 판정하는 기준이 아니라 변경 가능한 참고 범위입니다. 맛과 추출 의도를 바탕으로 무엇을 바꿀지 결정하고, 측정값과 회차별 변화를 살펴보는 데 사용하세요. Class는 수강생·실습별 기록과 강사 피드백을 지원합니다. 노트는 선택 사항이며 맛을 자동 분석하지 않습니다.

기본 Classic Filter 타겟 프로필은 공개된 SCA 브루잉 자료를 참고해 수율 18–22%, TDS 1.15–1.35% 범위로 시작합니다. 출발점으로 제공하는 참고 범위입니다. 타겟·차트 축·Brew Ratio·액체 보유 가정은 변경 가능하며, 보편적인 관능 품질 기준이나 물리적 한계로 해석하지 마세요.

추출액 또는 물양 중 하나를 비우면 다른 질량, 원두량, 측정 TDS와 액체 보유계수로 같은 질량수지 관계를 사용해 추정합니다. 추정 물양과 비율은 추출 중단 시 드리퍼에 남은 여분의 액체를 복원하지 않습니다. 기본 계수는 2.1이며 별도로 변경할 수 있습니다. 수율은 입력한 측정값과 가정에 의존합니다.

저장된 Quick·Class 기록은 수정 시에도 해당 기록의 보유계수를 사용합니다. 새 LIVE 계산과 비율 참고선은 현재 전역 설정을 사용합니다. schema v5 이전 기록은 이관 당시 데이터셋 계수를 부여해 직전 표시값을 보존하며 알 수 없는 과거 계수를 복원하지 않습니다. 추출액을 직접 입력한 EY에는 이 계수가 사용되지 않지만 물양·비율 역산에는 사용됩니다. schema v5 이하에서 이관한 기록의 기존 물양 입력 해석도 유지됩니다.

독립 프로젝트입니다. Specialty Coffee Association과 제휴하거나 승인을 받은 프로젝트가 아니며 SCA 로고·차트 원화를 포함하지 않습니다.

화면 배치와 수업 활용

분리 모드는 입력과 차트를 별도 화면으로, 지원되는 넓은 화면의 통합 모드는 Quick 또는 Class 입력과 해당 차트를 나란히 보여줍니다. 표시 방식·입력:차트 비율·입력 영역 크기·차트 크기는 저장·백업됩니다. 작은 입력 영역은 넓은 화면의 정밀 포인터 환경에 적용하며 터치·좁은 화면에서는 기본 크기를 사용합니다.

반·수강생·실습은 Class 관리 패널에서 관리합니다. 차트 도구에는 가이드·표시 선택·차트/타겟 설정 이동·이미지 복사·PNG 저장·공유가 있습니다. 한눈에 보기는 사용 가능한 높이에 맞추고, 크게 보기는 너비를 활용하며 세로 스크롤을 허용합니다. 좁은 화면에서는 차트를 너비에 맞추고 크기 선택을 비활성화하되 넓은 화면의 선택은 보존합니다. 화면 배치는 출력 이미지의 기하 구성을 바꾸지 않습니다.

측정기

HM Digital BTR-1000 / RCM-1000BT는 Web Serial, DiFluid R2는 Web Bluetooth로 선택적으로 연결합니다. R2의 Auto·횟수는 연결된 장치의 확인값을 사용하고 PC 요청도 같은 횟수를 사용합니다. 장치 Average는 확정된 최종 평균을 사용합니다. 장치에서 자동 시작된 Auto 다회 Single→Loop에만 마지막 N개 Loop 값을 평균하며, N개 미만이면 마지막 Loop 값을 사용합니다. 그 밖의 Single→Loop는 최종값을 사용합니다.

측정은 현재 Quick·Class TDS 입력을 채우며 기록을 자동 저장하지 않습니다. 입력 대상 변경이나 직접 TDS 수정은 결과 반영을 취소하고 이미 전송된 측정은 종료까지 추적합니다. 최종 데이터가 누락되면 기존 TDS를 유지하고 명시적 재연결이 필요합니다. 범위 밖의 숫자 측정값도 입력에 보존되지만 계산과 저장은 각각의 유효성 검사를 적용합니다.

1. 운영자와 적용 범위

Coffee Brewing Control은 Taehee Yoon(EHmade)이 운영하는 커피 추출 도구입니다. 이 안내는 공식 웹페이지 https://ehmade.github.io/brewing-control/와 배포된 원본 파일의 로컬 실행에서 앱이 데이터를 처리하는 방식을 설명합니다.

공식 웹페이지에서는 방문·성능 분석을 사용합니다. file: 로컬 파일, localhost 개발 주소 및 공식 앱 이외의 주소에서 실행하는 원본 앱은 해당 분석 스크립트를 로드하지 않습니다. 브라우저나 운영체제, 확장 프로그램 및 사용자가 선택한 공유 서비스의 별도 동작까지 이 앱이 제어하는 것은 아닙니다.

2. 앱에 입력한 기록

Quick 입력과 저장 기록, 반·수강생·실습 기록, 노트·강사 피드백, 타겟·차트 프로필과 설정은 사용자의 브라우저에 저장됩니다. 임시 편집 상태와 저장 복구를 위한 사본이 함께 유지될 수 있습니다. 앱은 이러한 데이터를 운영자의 서버에 자동 업로드하거나 방문 분석 이벤트로 보내지 않습니다. 운영자는 앱을 통해 사용자의 로컬 기록을 조회하거나 원격 삭제하는 기능을 제공하지 않습니다.

같은 컴퓨터의 같은 브라우저 프로필을 공유하는 사람은 기록에 접근할 수 있습니다. 브라우저/기기 변경, 저장소 정리, 비공개 모드 또는 저장 용량 제한으로 기록이 유지되지 않을 수 있으므로 필요한 데이터는 JSON 백업으로 보관해 주세요. 학생별 기록을 작성하는 경우 사용하는 이름과 노트에 불필요한 개인정보를 넣지 않는 것이 좋습니다.

개별 삭제와 설정의 전체 앱 데이터 초기화로 앱 데이터를 정리할 수 있습니다. 전체 초기화는 앱에서 사용하는 기록과 설정·복구 사본을 정리하지만, 사용자가 이미 내보낸 파일, 클립보드·공유 대상 및 외부 서비스의 방문 통계는 삭제하지 않습니다. 앱을 더 이상 사용할 수 없다면 해당 사이트의 브라우저 저장 데이터를 직접 삭제할 수도 있습니다.

표시 언어는 별도의 브라우저 선호로 저장합니다. 추출 백업에는 넣지 않으며 복원 후에도 유지하고 전체 초기화 시 삭제합니다.

3. 측정기 연결

지원되는 HM Digital 또는 DiFluid R2 측정기는 브라우저의 장치 API를 통해 직접 연결합니다. 성공적으로 적용된 TDS는 일반 입력과 같은 경로로 처리되며 기록 저장은 사용자가 실행합니다. 장치의 연결 객체와 보조 측정 정보는 앱 기록이나 백업에 저장하지 않습니다. 선택한 Device Profile과 측정기 컨트롤 표시 설정은 저장될 수 있지만, 실제 연결과 R2의 Auto/Count 상태는 백업하지 않습니다. 이 통신을 위한 운영자 중계 서버는 없습니다.

4. 공식 사이트의 방문·성능 분석

공식 웹페이지는 방문량과 유입 경향, 접속 환경 및 페이지 성능을 파악하기 위해 Cloudflare Web Analytics를 사용합니다. 공식 분석 스크립트는 Cloudflare에서 내려받으며, 페이지 주소·유입 페이지·접속 환경과 로딩/반응성/화면 안정성 등 방문·성능 정보가 Cloudflare로 전송됩니다. 장기간 특정 사용자를 식별하거나 Quick/Class 조작과 추출 기록을 연결하는 맞춤 이벤트는 구현하지 않습니다.

Cloudflare는 공식 RUM 문서에서 Beacon이 쿠키·localStorage·sessionStorage·IndexedDB와 같은 브라우저 저장소에 접근하거나 데이터를 저장하지 않는다고 설명합니다. 또한 통상적인 요청 처리 중 수신하는 IP 주소는 가까운 데이터센터에서 폐기하고 핵심 데이터베이스나 로그에 저장하지 않는다고 설명합니다. 이는 공급자의 해당 서비스 동작 설명이며, 외부 JavaScript를 브라우저 수준에서 별도 격리한다는 뜻은 아닙니다.

앱은 수강생 정보, 반·실습 기록, 노트, 피드백, Dose/TDS/EY 값이나 백업 JSON을 분석 요청에 연결하는 기능을 추가하지 않습니다. 이 정보는 분석용 URL이나 사용자 식별값으로 사용하지 않습니다.

분석 스크립트를 차단하거나 네트워크 연결에 실패해도 핵심 계산·기록·차트·측정기 기능은 사용할 수 있도록 구성합니다. 방문 통계는 차단 도구, 브라우저 지원 및 서비스 설정의 영향을 받으므로 실제 사용자 수나 반복 사용 여부를 정확히 나타내는 수치는 아닙니다.
