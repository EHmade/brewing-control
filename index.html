계산 설정
Liquid retention · 2.1×
물양 또는 Beverage 중 하나를 비워두면 원두층에 남는 액체량을 이 계수로 가정해 자동 추정합니다. Beverage = [물양 − (계수 × 원두량)] ÷ (1 − TDS/100)
물양 = Beverage × (1 − TDS/100) + 계수 × 원두량 현재 계수는 새 LIVE 계산과 신규 기록, 차트의 Brew Ratio 가이드에 적용됩니다. 저장된 기록은 보존된 계수를 사용하며, 구버전 기록은 이관 당시 계수로 표시값을 유지합니다. 실제 Beverage를 직접 입력한 기록의 EY 계산에는 이 계수가 사용되지 않습니다. 물양이 비어 있으면 물양과 Ratio 추정에는 보존된 계수가 적용됩니다. 기본값은 2.1입니다.

About & References

Coffee Brewing Control is a browser-based tool for working toward the extraction targets you choose. It brings measurement, brew records, chart interpretation, and adjustment guidance together for repeated personal testing and barista practice sessions. No app installation is required. Direct TDS input from supported refractometers is available in compatible browsers and operating systems. Target ranges are configurable references, not a verdict on flavor or quality. Use tasting and your brewing goals to decide what to change; the app helps you examine the measurements and follow changes across attempts. Class supports student and practice-session records with instructor feedback. Notes are optional and are not automatically analyzed for flavor.

The built-in Classic Filter target profile uses a default reference range of 18–22% extraction yield and 1.15–1.35% TDS, informed by published SCA brewing materials. This range is provided as a starting reference only.

Target ranges, chart scales, brew ratios, and liquid-retention assumptions are configurable. User-defined targets and chart ranges should not be interpreted as established sensory-quality standards or physical limits.

When either beverage mass or brew water is left blank, the tool estimates the missing mass from the other mass, dose, measured TDS, and the configured liquid-retention value using the same mass-balance relationship. Estimated brew water and its Brew Ratio are reference estimates; extra liquid left in the dripper when brewing is stopped is not reconstructed. The default liquid-retention reference is 2.1 and remains independently configurable. Calculated extraction yield therefore depends on the measurements and assumptions provided by the user.

Saved Quick and Class records retain their liquid-retention value when edited. New LIVE calculations and Brew Ratio guides use the current global setting. Older records migrated to schema v5 receive the dataset's retention value at migration, preserving their preceding displayed results rather than reconstructing an unknown historical value. EY calculated from directly entered Beverage remains independent of this coefficient; estimating Brew water and Ratio still uses it. Records migrated from schema v5 or earlier retain their previous water-input interpretation.

Independent project. This project is independently developed and is not affiliated with or endorsed by the Specialty Coffee Association. No SCA logo or SCA chart artwork is included.

Layouts and classroom workflow

Split mode keeps inputs and the chart on separate screens. On supported wide screens, integrated mode shows Quick or Class inputs beside the corresponding chart. Display mode, input-to-chart ratio, input size, and chart size are saved and included in JSON backups. Compact inputs apply on wide screens with a fine pointer; touch and narrow screens use the default size.

Class, student, and practice management are in the Class context panel. Chart Tools contains guide and selection controls, a Chart / Target Settings shortcut, and image copy, PNG, and sharing controls. Fit to screen uses available height; Large uses available width and permits vertical scrolling. The on-screen layout does not change exported chart geometry.

Measurement devices

Optional device profiles support HM Digital BTR-1000 / RCM-1000BT through Web Serial and DiFluid R2 through Web Bluetooth. R2 Auto and measurement Count follow the connected device; PC requests use the same Count. Device Average uses the reported final average. Only device-origin Auto multi-measurement Single-to-Loop cycles use the last N received Loop readings, with the final Loop reading used if fewer than N are available. Other Single-to-Loop measurements use their final reading.

Measurements fill the current Quick or Class TDS input without saving a record. Changing the input target or manually editing TDS cancels delivery; an already sent device measurement remains tracked until it ends. Missing final data preserves the previous TDS and requires explicit reconnection. Received numeric values remain visible even outside the brewing-calculation interval; calculation and record saving apply their own validity checks.

Data & privacy

Brew measurements, class data, notes, feedback, profiles, and settings are stored in your browser. The app does not automatically upload these records to an application backend or send them as analytics events. Device communication is direct through browser APIs. JSON backup, image export, copy, and sharing occur at your request.

The official hosted site uses Cloudflare Web Analytics for site visits and page performance. Related visit and performance information is processed by Cloudflare separately from your brew and class records. The original app does not load the analytics script when opened as a local file, on localhost, or at other site paths. Analytics blocking or loading failure does not prevent the core app from working.

Privacy & Data Handling · 개인정보 및 데이터 처리 안내

Questions can be posted in public GitHub Issues. Do not post personal records or raw backups there.

Version 4.5.3 uses schema v7 with the existing storage key and backup format. Import rejects files above 32 MiB and excessive text or data structures without truncation; passing validation does not guarantee browser storage capacity. Export a backup and close older app tabs before upgrading in the same browser storage context. Keep a pre-upgrade backup for rollback; versions before 4.4.3 do not participate in the reset-generation protection. Unreadable or newer-schema stored data stops automatic writes, and raw recovery export remains available. Conflicting tabs preserve their in-memory content for export.

Changelog

All notable changes to Coffee Brewing Control are documented here. Earlier development history is intentionally condensed to major milestones.

4.5.3 - 2026-10-27

Added

  • Added Korean / English search metadata, a canonical URL, Open Graph cards, and an original social-preview image based on the app chart.
  • Added the user-issued Google Search Console verification tag and a single-URL sitemap.
  • Added an independent Cloudflare Web Analytics loader restricted to the official HTTPS app entry paths, with SPA tracking disabled.
  • Added Privacy & Data Handling, including a readable local HTML page generated from the same Markdown source.

Changed

  • Reorganized README around first use, brewing workflows, targets, display options, devices, data, and operation; corrected outdated current-version and R2 compatibility wording.
  • Aligned About, README, and privacy guidance with user-defined extraction goals and the distinction between local brew records and hosted visit analytics.

Compatibility

  • Schema v7, the storage key, backup format, brewing calculations, display preferences, device protocols, and chart-image export remain unchanged.
  • Local and non-official app copies do not request the analytics script. Analytics is not a prerequisite for core app operation.

4.5.2 - 2026-10-26

Added

  • Added a saved chart-size choice: Fit to screen (default) or Large with vertical scrolling, in both split and integrated modes. Chart-image export is independent of this choice.
  • Added an optional integrated layout showing Quick or Class inputs beside the corresponding chart, with shared 35:65, 40:60, and 45:55 input-to-chart ratios.
  • Added Default / Compact input-area sizing for sufficiently wide screens with a fine pointer. Touch and narrow screens use the default size while retaining the saved preference.
  • Added a Chart / Target Settings shortcut inside Chart Tools. It moves to the relevant Settings sections without opening them automatically.

Changed

  • Chart Tools and Class management now open or close by clicking their header text or empty space, with unboxed plus / minus indicators. Buttons inside the header retain their own actions and native keyboard controls remain available.
  • Split mode remains the default. Quick and Class open their corresponding chart, including an empty Class; the chart can return to the corresponding input screen.
  • Chart Tools groups guide, goal, student / attempt selection, and image copy / PNG / sharing controls. Collapsing it hides the controls while retaining the summary and full out-of-range warning.
  • Reduced on-screen chart whitespace and used the available viewport height while retaining minimum readability. Short screens or expanded controls can still require scrolling.
  • Moved class, student, and practice management into the Class context panel with a compact summary and expandable tabs; practice selection and creation are in the practice tab.
  • Stabilized Settings width, scrolling, mode-selection spacing, and Quick / Class transitions. A selected display mode is applied when leaving Settings.
  • Unified device-header space and mobile navigation-pill sizing, prevented the student Add button from wrapping, clarified storage and display guidance, and formatted HTML / CSS / JavaScript with LF line endings.

Fixed

  • Preserved native keyboard focus and Tab order after using the Chart / Target Settings shortcut; target and chart sections remain operable with Enter and Space.

Compatibility

  • Schema remains v7. Display mode, input-to-chart ratio, input size, and chart size are saved and backed up; older supported backups receive defaults. Earlier app versions may discard these new preferences.
